# Ревизия и актуализация проекта

Эта папка — рабочая точка входа для последовательного возвращения проекта в
поддерживаемое состояние. Документы фиксируют срез на **29 июля 2026 года**;
результаты проверки зависимостей следует повторить, когда npm registry снова
будет доступен из окружения.

## Порядок работы

1. [`final-audit-2026-07-29.md`](final-audit-2026-07-29.md) — итоговая
   проверка модернизированной реализации, performance и тестовых контуров.
2. [`current-state-2026-07-29.md`](current-state-2026-07-29.md) — прочитать
   подтверждённый срез работоспособности и список проблем.
3. [`modernization-roadmap.md`](modernization-roadmap.md) — выполнять этапы по
   порядку, не смешивая восстановление baseline с архитектурным рефакторингом.
4. [`open-questions.md`](open-questions.md) — закрывать продуктовые и
   архитектурные развилки до реализации соответствующего этапа.

## Правило обновления

После каждого этапа:

- добавить ссылку на PR/коммит и дату в roadmap;
- перенести решённые вопросы из `open-questions.md` в секцию «Принятые
  решения» этого файла;
- повторить проверки этапа 0 и зафиксировать новые отклонения в отдельном
  датированном отчёте, не переписывая исторический срез.

## Принятые решения

Продуктовые и архитектурные решения зафиксированы в
[`open-questions.md`](open-questions.md); итоговая проверка реализации и
оставшиеся release-риски — в
[`final-audit-2026-07-29.md`](final-audit-2026-07-29.md).
